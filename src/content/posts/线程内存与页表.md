# 线程、内存与页表：结构与软硬件边界

## 核心结论

一句话概括：

> **地址空间和页表通常属于进程；线程控制块、执行上下文和用户栈属于线程；堆、代码和全局数据通常由同一进程的线程共享。**

线程并不是“把页表、栈和堆全部包在里面”的对象。更准确的关系是：

- 操作系统创建地址空间，并为它维护页表。
- 同一进程中的线程共享这个地址空间和页表。
- 每个线程有独立的执行上下文和控制块。
- 每个线程通常有独立的用户栈。
- 堆、代码、全局数据和文件映射通常由同进程线程共享。
- 页表只负责虚拟地址到物理地址的映射和权限检查，不负责区分“这块内存属于哪个线程”。

---

## 1. 总体结构

```text
应用与运行时
├── 线程函数、局部变量、动态对象、TLS
├── 线程库：pthread/TCB、线程栈、堆分配器
└── 编译器、链接器：生成虚拟地址和机器指令
            │
            ▼
操作系统内核
├── 进程对象：地址空间、文件、信号、权限
├── 线程对象：TCB、调度状态、用户栈/内核栈
├── 页表、VMA（虚拟内存区域）、物理页管理
└── 调度器、异常和系统调用入口
            │
            ▼
ISA 接口
├── 寄存器、PC、SP
├── 虚拟地址格式、页表格式、页权限
├── 特权级、异常、中断、TLB 管理
└── load/store 和上下文切换所需指令
            │
            ▼
CPU 微架构
├── 执行流水线、寄存器堆、ALU
├── MMU、TLB、Cache、物理内存接口
└── 执行 load/store，完成地址翻译和权限检查
```

可以把软硬件边界理解为：

- **软件决定“希望怎样组织和访问内存”**：进程、线程、栈、堆、页表内容和访问策略。
- **硬件决定“怎样执行和强制检查”**：MMU 查页表、TLB 缓存翻译、CPU 检查权限、在越权时触发异常。

## 2. 进程与线程

### 2.1 进程提供什么

进程可以理解为一个运行程序所拥有的资源和执行环境，通常包括：

- 一个用户虚拟地址空间。
- 一套页表和虚拟内存区域。
- 打开的文件、网络连接等资源。
- 信号处理配置。
- 用户身份和权限信息。
- 一个或多个执行线程。

因此，进程更接近“资源容器和隔离边界”。

### 2.2 线程提供什么

线程是进程中的一条执行流。每个线程通常有：

- 程序计数器 PC。
- 栈指针 SP。
- 通用寄存器和浮点寄存器现场。
- 调度状态和优先级。
- 用户栈。
- 线程局部存储 TLS。
- 线程控制块 TCB。
- 内核调度线程通常还有独立的内核栈。

因此，线程更接近“CPU 执行上下文的软件抽象”。

### 2.3 同进程线程共享什么

同进程线程通常共享：

- 虚拟地址空间。
- 页表。
- 代码段。
- 全局变量和静态变量。
- 堆。
- 文件描述符和多数进程资源。

不同线程通常不共享：

- PC、SP 和寄存器现场。
- 用户栈。
- 调用帧和局部变量区域。
- TLS。
- 调度状态。
- 内核栈。

## 3. 线程控制块 TCB

线程的“头”通常称为 **TCB，Thread Control Block**。

TCB 不是 CPU 强制规定的硬件结构，而是操作系统或线程库定义的软件数据结构。

### 3.1 TCB 常见内容

| 内容         | 作用                         |
| ------------ | ---------------------------- |
| PC           | 下一条要执行的指令地址       |
| SP           | 当前线程栈顶或当前调用帧位置 |
| 寄存器保存区 | 线程被换出时保存 CPU 现场    |
| 线程状态     | 运行、就绪、阻塞、终止       |
| 调度信息     | 优先级、时间片、CPU 亲和性   |
| TLS 指针     | 找到线程局部存储             |
| 地址空间指针 | 指向所属进程的地址空间       |
| 内核栈指针   | 系统调用和中断时使用         |
| 等待对象     | 锁、条件变量、I/O 等         |

### 3.2 用户级 TCB 与内核级 TCB

同一个逻辑线程可能同时对应两类控制结构：

- **用户线程库中的 TCB**：例如 C 线程库中的 `pthread` 描述结构。
- **内核中的 TCB**：例如 Linux 的 `task_struct`。

`pthread_t` 是线程库提供给程序的标识，在部分实现中可能是指向内部线程结构的指针，但不是可移植的硬件结构。

### 3.3 TCB 是否直接指向堆

通常不是。

TCB 主要保存执行上下文和关联指针：

- 它通常直接保存或间接引用自己的栈。
- 它保存所属地址空间。
- 它一般不会保存一个“本线程私有的堆指针”，因为堆通常是进程级的。

## 4. 线程内存布局

### 4.1 常见区域

| 区域     | 典型内容                         | 同进程线程是否共享 |
| -------- | -------------------------------- | ------------------ |
| text     | 机器指令                         | 共享               |
| rodata   | 只读常量                         | 共享               |
| data/BSS | 全局变量、静态变量               | 共享               |
| heap     | `malloc/new` 动态对象            | 通常共享           |
| 用户栈   | 局部变量、参数、返回地址、调用帧 | 每线程独立         |
| TLS      | `thread_local` 数据              | 每线程独立         |
| 内核栈   | 系统调用、中断、内核执行现场     | 每线程独立         |

### 4.2 一个进程、两个线程

```text
进程地址空间
├── text：所有线程共享
├── rodata：所有线程共享
├── data/BSS：所有线程共享
├── heap：所有线程通常共享
├── 映射区
│   ├── 线程1用户栈
│   └── 线程2用户栈
│
├── TCB1：PC、SP、寄存器、TLS、调度状态
└── TCB2：PC、SP、寄存器、TLS、调度状态
```

注意：TCB 不一定和线程用户栈连续存放。TCB 可能由线程库分配，也可能位于内核内存；用户栈通常是另一段虚拟内存区域。

### 4.3 线程栈不是硬件隔离区

线程栈只是进程地址空间中的一个映射区域。其他线程如果获得指向该栈的地址，并且页权限允许，就可能读写它。

线程之间“栈不能互相访问”主要是软件约定和程序正确性问题，不是 CPU 按线程 ID 自动隔离的。

### 4.4 堆不是默认每线程一份

标准的多线程进程中：

- 堆位于共享地址空间。
- 一个线程分配的对象，可以被另一个线程通过指针访问。
- 线程库的分配器可能使用 per-thread arena 减少锁竞争，但 arena 不是硬件隔离的线程私有堆。

## 5. 页表的结构

### 5.1 页表做什么

页表负责把虚拟地址翻译为物理地址，并检查访问权限。

基本关系：

```text
虚拟地址 = 虚拟页号 VPN + 页内偏移 offset
物理地址 = 物理页框号 PFN + 页内偏移 offset
```

页内偏移在翻译过程中通常保持不变：

```text
VPN  ──页表──> PFN
offset ──────> offset
```

### 5.2 页表项 PTE

一个页表项通常包含：

- 物理页框号 PFN。
- 是否有效。
- 是否可读。
- 是否可写。
- 是否可执行。
- 用户态是否可访问。
- 访问位和脏位。
- 缓存属性。

页表项描述的是**页和权限**，通常不记录：

- 哪个线程正在使用它。
- 这块页叫“线程1的栈”还是“堆”。
- 属于哪个 C/C++ 变量。

### 5.3 页表与 VMA 的区别

在 Linux 中，页表和 VMA 分工不同：

- **页表**：当前哪些虚拟页映射到了哪些物理页，以及权限是什么。
- **VMA**：哪些虚拟地址范围属于代码、堆、栈、共享库或文件映射。

VMA 属于地址空间管理结构，通常由 `mm_struct` 管理。线程共享地址空间，因此也共享这些 VMA。

### 5.4 多级页表

为了减少页表占用的空间，现代 CPU 常使用多级页表：

```text
虚拟地址
├── 一级页表索引
├── 二级页表索引
├── 三级页表索引
├── 页内偏移
```

不同架构的级数和名称不同：

- x86-64 常见 4 级或 5 级页表。
- ARM64 常见 4 级页表。
- RISC-V 可使用 Sv39、Sv48 等方案。
- MIPS 也有自己的 TLB 和内存管理模型。

具体级数不影响核心关系：**页表属于地址空间，线程共享地址空间时也共享页表。**

### 5.5 MMU 与 TLB

地址翻译过程：

```text
CPU 执行 load/store
        │
        ▼
产生虚拟地址
        │
        ▼
查询 TLB
   ├── 命中：得到物理地址
   └── 未命中
        ├── MMU 遍历页表
        ├── 检查有效位和权限
        ├── 填充 TLB
        └── 得到物理地址或触发异常
        │
        ▼
访问 Cache / 物理内存
```

需要区分：

- **页表**：由操作系统维护的主要地址映射结构。
- **MMU**：CPU 中执行地址翻译和权限检查的硬件。
- **TLB**：MMU 使用的翻译缓存，不是页表本身。
- **VMA**：操作系统用于描述虚拟区域语义的软件元数据。

## 6. 线程、栈、堆和页表的对应关系

### 6.1 线程与页表

```text
进程 = 一个地址空间
    └── 页表根
         ├── 代码页映射
         ├── 堆页映射
         ├── 线程1栈页映射
         └── 线程2栈页映射

线程1 TCB ──> 共享同一个地址空间
线程2 TCB ──> 共享同一个地址空间
```

同进程线程通常共享同一套页表根地址，但它们的 SP、PC 和寄存器现场不同。

### 6.2 线程与栈

- TCB 保存当前线程的 SP。
- SP 指向该线程当前调用帧附近。
- 该栈是一段虚拟地址范围。
- 这段虚拟范围由页表映射到物理页。
- 栈通常带保护页，防止越界继续向下扩展。

### 6.3 线程与堆

- 堆是进程级共享区域。
- 堆分配器用软件元数据管理空闲块和已分配块。
- 线程通过虚拟地址访问堆对象。
- MMU 根据页表把虚拟地址翻译成物理地址。
- 页表不记录对象大小、变量类型或分配者线程。

### 6.4 指针到底是什么

C/C++ 中的指针通常保存一个**虚拟地址**，不是物理地址。

```text
线程栈中的指针
      │
      ▼
虚拟地址
      │
      ▼
MMU + 页表
      │
      ▼
物理地址
```

因此：

- 指针不天然属于某个线程。
- 指针也不天然指向某个线程私有堆。
- 只要虚拟地址在当前地址空间中有效且权限允许，其他线程也可以使用同一个指针。
- 同一个物理页还可以同时映射到多个进程的不同虚拟地址，例如共享内存或写时复制。

## 7. 上下文切换

### 7.1 同进程线程切换

```text
保存线程1：
  PC、SP、通用寄存器 ──> TCB1

恢复线程2：
  TCB2、PC、SP、通用寄存器 ──> CPU
```

由于两个线程属于同一进程：

- 页表通常不切换。
- 地址空间不切换。
- 代码、全局数据和堆仍然可见。
- 当前执行栈切换。
- TLB 中的相关翻译通常可以继续使用。

### 7.2 不同进程切换

除了保存和恢复线程现场，还要切换地址空间：

- 加载新进程的页表根地址。
- 例如 x86 使用 `CR3`。
- 必要时处理 TLB 刷新或使用 PCID/ASID 区分地址空间。

### 7.3 硬件在这里做什么

CPU 通常不主动理解“这是 Java 线程”“这是 pthread”或“这是线程1的堆”。

CPU 实际执行的是：

- 当前 PC 上的指令。
- 当前寄存器中的值。
- 当前页表根所定义的地址翻译。
- 当前特权模式下允许的操作。

调度器决定“下一个运行哪个线程”；CPU 负责执行恢复后的现场。

## 8. 软件与硬件的职责边界

| 机制           | 软件职责                       | 硬件职责                       |
| -------------- | ------------------------------ | ------------------------------ |
| 进程和线程对象 | 创建、销毁、状态转换、调度     | 提供执行上下文和异常机制       |
| 页表内容       | OS 分配页、填写 PTE、设置权限  | MMU 读取 PTE 并执行翻译        |
| 虚拟地址       | 编译器、链接器、分配器生成地址 | load/store 产生并处理虚拟地址  |
| TLB            | OS 在需要时失效相关项          | TLB 自动缓存翻译结果           |
| 越权访问       | OS 配置页权限和特权规则        | CPU 在访问时强制检查并触发异常 |
| 用户栈         | 线程库/OS 分配栈范围和保护页   | SP 寄存器及 load/store 使用它  |
| 堆             | 分配器管理空闲块和元数据       | 不提供“堆”这个硬件对象         |
| 调度           | OS 调度器选择下一个线程        | 定时器中断、保存/恢复现场指令  |
| Cache          | OS 配置策略、必要时维护一致性  | Cache 自动缓存数据并按策略替换 |
| 中断和系统调用 | OS 注册处理逻辑并完成服务      | 保存现场、切换特权级、跳转入口 |

最重要的边界是：

> **“线程、栈、堆、VMA”是软件抽象；“寄存器、MMU、TLB、Cache、页表遍历和权限异常”是硬件执行机制。**

## 9. 一个具体例子

假设一个进程中有两个线程 T1、T2：

```text
进程 P
├── 地址空间 A
│   ├── text 映射
│   ├── data 映射
│   ├── heap 映射
│   ├── T1 用户栈映射
│   └── T2 用户栈映射
│
├── TCB1
│   ├── PC = text 中的指令地址
│   ├── SP = T1 栈中的当前帧地址
│   └── mm = A
│
└── TCB2
    ├── PC = text 中的另一条指令地址
    ├── SP = T2 栈中的当前帧地址
    └── mm = A
```

T1 要访问一个堆对象时：

1. T1 的代码产生虚拟地址。
2. CPU 执行 load/store。
3. MMU 根据进程 P 的页表翻译地址。
4. TLB 命中则直接得到物理地址，未命中则遍历页表。
5. 权限允许则访问 Cache/物理内存，否则触发异常。

当切换到 T2：

1. T1 的 PC、SP 和寄存器保存到 TCB1。
2. 恢复 TCB2 的 PC、SP 和寄存器。
3. 页表不变，因为 T1、T2 共享地址空间 A。
4. T2 可以继续访问同一个堆，但使用自己的栈。

## 10. 常见误区

### 误区一：每个线程都有自己的页表

错误。通常是一套地址空间对应一套页表，同进程线程共享页表。

### 误区二：每个线程都有自己的堆

不准确。堆通常是进程级共享的。某些分配器会使用线程本地 arena，但内存仍然属于同一地址空间。

### 误区三：线程头直接包含线程的全部内存

错误。TCB 保存执行状态和指针，不包含整个栈、堆和地址空间。

### 误区四：页表知道哪块内存属于哪个线程

错误。页表知道虚拟页、物理页和权限，不知道线程语义。栈和堆的语义主要由 OS 的 VMA 和软件数据结构描述。

### 误区五：栈是 CPU 强制隔离的线程私有内存

不准确。栈是线程私有使用约定的虚拟内存区域，其他线程在地址空间内仍可能访问它。

### 误区六：指针保存物理地址

错误。普通进程中的指针保存虚拟地址，物理地址由 MMU 根据页表翻译得到。

## 11. 适合放入 PPT 的简版表述

1. **进程是地址空间和资源容器，线程是执行流。**
2. **页表通常属于地址空间，同进程线程共享页表。**
3. **每个线程有独立 TCB、PC、SP、寄存器现场和用户栈。**
4. **堆、代码、全局数据通常由同进程线程共享。**
5. **TCB 保存执行上下文，不保存整个线程内存。**
6. **指针是虚拟地址，MMU 通过页表把它翻译为物理地址。**
7. **软件定义线程、栈、堆和页表内容；硬件执行翻译、权限检查和异常处理。**
8. **同进程线程切换通常不换页表；不同进程切换需要切换地址空间。**
9. **线程栈不是硬件按线程 ID 隔离的私有内存。**
10. **页表不知道“线程”或“堆”的语义，只知道页映射和访问权限。**
